# 数据与备份

> [← 返回 README](../README.md) · [架构与数据模型](architecture.md) · [同步与加密](sync.md)

除了云端同步，三端都能把全部记录导成一份 JSON、再互相导入。导出的 JSON 是**明文**——恢复时不依赖任何密钥，这也是服务器出事时最后一道保险。

## 导入 / 导出入口

| 位置 | 操作 |
|:---|:---|
| 网页版 | 清单页「导出」→「数据备份」→ 导出文件 / 复制内容 / 从文件恢复 / 粘贴恢复 |
| 原生版 | 底部「设置」→「数据备份」→ 导出备份 / 导入备份 |

- 导出走系统「保存到…」，文件名 `每日任务清单备份-yyyy-MM-dd.json`
- 导入先弹窗列出「多少天 / 多少条 / 已完成多少」，再让用户选 **合并** 或 **覆盖**
  - **合并**：只补本机没有的任务（同 id，或同一天里同名同学科视为已有），不动现有记录
  - **覆盖**：先清空再写入，主题 / 标签 / 打卡一并恢复
- 任意一端导入过后会置 `_seeded` 标记，示例任务不会再冒出来混进真实记录

## 备份格式

`schema = 1`，三端共用：

```json
{
  "app": "daily-task-list",
  "schema": 1,
  "exportedAt": "2026-11-05T01:20:00+08:00",
  "tasks":    { "2026-08-26": [ { "id", "title", "subject", "note", "done", "createdAt" } ] },
  "study":    { "2026-08-26": { "hours", "start", "place", "review" } },
  "checkins": [ "2026-08-26" ],
  "subjects": [ { "key": "math", "name": "数学", "color": "#4C8DFF" } ],
  "settings": { "theme": "#4BC85C", "showCompletion": true, "sort": "manual" }
}
```

- 颜色统一写 `#RRGGBB`；导入时也认原生版的 `0xAARRGGBB` 数字和 `"0x..."` 字符串
- `checkins` 同时接受数组（原生版）和 `{ "日期": { "time": "" } }` 对象（网页版旧格式）

## 旧版 PDF 历史记录迁移

旧版 App 只能导出 PDF，而那份 PDF 的字体是子集化的 Noto Sans CJK（Identity-H + 自定义字形序号），直接用 `pdftotext` / PyMuPDF 读出来全是 `456#$7869:6;<6=>?@` 这种乱码。PDF 里其实带了完整的 ToUnicode 映射表，所以 `scripts/legacy-pdf-import.py` 自己解析 CMap 还原正文，再按表格拆成任务：

```bash
python scripts/legacy-pdf-import.py 任务数据.pdf \
    --append backup/补录-11月2-4日.txt --year 2026 \
    -o backup/每日任务清单备份-2026-11-04.json
# 补录 backup/补录-11月2-4日.txt: 14 条任务
# 日期范围: 2026-08-26 ~ 2026-11-04（69 天）
# 任务总数: 447  已完成: 332  未完成: 115  完成率: 74%
# 学习详情: 3 天
```

注意事项：

- PDF 部分的结果会跟它自带的「总体统计」对一遍（433 / 318 / 115 / 73%），数字对上才算成功
- `--append` 吃的是 App「导出每日计划」原样的文本（`【11月4日学习任务】` 那种），用来补 PDF 之后新增的几天；只有「几月几日」没有年份，用 `--year` 补全
- 补录文本里没有完成状态，一律按「已完成」写入（这些天都已经过完），导入后可在 App 里手动取消勾选
- 任务 id 用 36 进制时间戳生成，跟 App 自己的一致（如 `mvyhslc00`），不留任何外部标记
- 备注列在 PDF 里会折行、跨页，脚本会把续行拼回一条；分类「未分类」保留成独立标签，不并进「其他」
